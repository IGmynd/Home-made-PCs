# Байткод ПТ (PTBC v1)

Стековая виртуальная машина (ВМ). Одна и та же программа работает на ПТ, КПТ и роботе, на ПК она запускается
тем же кодом (`vm/vm.c`). Компилятор Слога и ассемблер создают файлы `.ptb`, ВМ их исполняет.

Главное свойство: **ВМ никогда не падает**. Любая ошибка программы (стек, память, переход, деление на ноль,
неизвестная команда, лимит шагов) возвращается кодом ошибки, и работа программы просто останавливается.
Система при этом продолжает жить.

## Устройство ВМ

- Ячейки 32 бита со знаком, порядок байтов little-endian.
- **Стек данных:** 256 ячеек. **Стек возвратов** (адреса `call`): 128 вызовов.
- **Код** отделён от данных: программа не может изменить свой код.
- **Память программы** делится на три области:

```
адрес 0                                                                    конец памяти
 ┌──────────┬────────────────────────┬─────────────────┬──────────────────┐
 │  данные  │  куча (растёт вверх)   │   свободно      │  кадры функций   │
 └──────────┴────────────────────────┴─────────────────┴──────────────────┘
            heap_base      heap_end                   fp (растут вниз)  fp_top
```

  Данные (глобальные переменные, константы) лежат внизу и берутся из образа. Куча растёт вверх от конца данных,
  кадры локальных переменных растут вниз от конца памяти. Когда они встречаются, команда, которой не хватило
  места, возвращает ошибку.
- Все обращения к памяти проверяются на границы. Целое число 32 бита, переполнение заворачивается.
- Выполнение начинается с байта 0 кода.

## Формат файла (.ptb)

| Смещение | Размер | Поле |
|----------|--------|------|
| 0 | 4 | magic `PTBC` |
| 4 | 2 | версия (1) |
| 6 | 2 | флаги (0) |
| 8 | 4 | длина кода |
| 12 | 4 | длина данных |
| 16 | | код, затем данные |

Данные копируются в память с адреса 0, остальная память обнуляется.

## Команды

Обозначения: `( до -- после )`, справа вершина стека. `u8` и `u32` это операнды в самом коде.

### Стек и константы

| Код | Имя | Операнд | Действие |
|-----|-----|---------|----------|
| 00 | `halt` | | завершить программу |
| 01 | `push8` | s8 | ( -- n ) число от -128 до 127 |
| 02 | `push32` | i32 | ( -- n ) |
| 03 | `dup` | | ( a -- a a ) |
| 04 | `drop` | | ( a -- ) |
| 05 | `swap` | | ( a b -- b a ) |
| 06 | `over` | | ( a b -- a b a ) |

Ассемблер команду `push` выбирает между `push8` и `push32` сам.

### Арифметика, логика, сравнения

| Код | Имя | Действие |
|-----|-----|----------|
| 10 | `add` | ( a b -- a+b ) |
| 11 | `sub` | ( a b -- a-b ) |
| 12 | `mul` | ( a b -- a*b ) |
| 13 | `div` | ( a b -- a/b ), результат обрезается к нулю |
| 14 | `mod` | ( a b -- a%b ), знак как у делимого |
| 15 | `and` | побитовое И |
| 16 | `or` | побитовое ИЛИ |
| 17 | `xor` | побитовое исключающее ИЛИ |
| 18 | `shl` | сдвиг a влево на b бит |
| 19 | `shr` | логический сдвиг вправо |
| 1A | `sar` | арифметический сдвиг вправо (знак сохраняется) |
| 1B | `neg` | ( a -- -a ) |
| 1C | `not` | ( a -- ~a ) |
| 20-25 | `eq ne lt le gt ge` | ( a b -- 0 или 1 ), знаковое сравнение |

Особые случаи: деление и остаток на ноль это ошибка. `-2147483648 / -1` даёт `-2147483648`, остаток 0.
Число бит сдвига берётся по модулю 32.

### Память

| Код | Имя | Действие |
|-----|-----|----------|
| 30 | `ld32` | ( адрес -- слово ), адрес может быть невыровненным |
| 31 | `st32` | ( значение адрес -- ) |
| 32 | `ld8` | ( адрес -- байт ), без знака |
| 33 | `st8` | ( значение адрес -- ), записывается младший байт |

### Переходы и вызовы

| Код | Имя | Операнд | Действие |
|-----|-----|---------|----------|
| 40 | `jmp` | u32 | безусловный переход (абсолютный адрес в коде) |
| 41 | `jz` | u32 | ( c -- ) переход, если c равно нулю |
| 42 | `jnz` | u32 | ( c -- ) переход, если c не равно нулю |
| 43 | `call` | u32 | вызов подпрограммы |
| 44 | `ret` | | возврат |

### Локальные переменные (кадры)

Нужны функциям с параметрами и рекурсии. Кадр хранится в верхней части памяти и растёт вниз.

| Код | Имя | Операнд | Действие |
|-----|-----|---------|----------|
| 60 | `frame` | u8 | создать кадр на n переменных (обнулены) |
| 61 | `leave` | | удалить текущий кадр |
| 62 | `ldl` | u8 | ( -- v ) значение локальной переменной i |
| 63 | `stl` | u8 | ( v -- ) записать в локальную переменную i |

Заголовок кадра хранит прежний указатель кадров и число переменных. ВМ проверяет его при каждом обращении,
поэтому испорченный кадр даёт ошибку, а не выход за память.

### Куча и метки памяти

| Код | Имя | Действие |
|-----|-----|----------|
| 52 | `alloc` | ( байты -- адрес ) выделить из кучи обнулённый блок, размер округляется до 4 |
| 53 | `heapmark` | ( -- метка ) запомнить границу кучи |
| 54 | `heapreset` | ( метка -- ) вернуть границу к метке: всё выделенное после неё освобождается |

Освобождения отдельных блоков нет. `heapreset` освобождает всё выделенное после метки сразу (дисциплина
«как стек»). Метка должна быть от начала кучи до текущей границы и кратна 4, иначе ошибка -6. Значения,
созданные после метки, после сброса недействительны: это забота программы, безопасность ВМ при этом не страдает.

### Системные команды

| Код | Имя | Операнд | Действие |
|-----|-----|---------|----------|
| 50 | `sys` | u8 | обращение к ОС, см. ниже |
| 51 | `trap` | u8 | остановить программу с ошибкой -13, код причины сохраняется в `trap_code` |

Компилятор Слога использует `trap` для кодов: 1 это индекс вне списка, 2 это недопустимый размер списка.

## Системные вызовы

Команда `sys n` обращается к ОС. Номера одинаковы для ПК (`vm/host.c`) и ядра ПТ (`kernel/kernel.c`).

| № | Имя | Действие |
|---|-----|----------|
| 1 | putc | ( c -- ) вывести байт |
| 2 | getc | ( -- c ) прочитать байт без ожидания, -1 если нет |
| 3 | readline | ( -- строка ) прочитать строку с консоли, ждать Enter. Байты UTF-8 превращаются в строку Слога, испорченные последовательности становятся символом U+FFFD |
| 4 | time | ( -- мс ) миллисекунды с запуска (32 бита, переходят через ноль примерно раз в 49 суток) |
| 5 | sleep | ( мс -- ) подождать столько миллисекунд |

Остальные номера зарезервированы (файлы, запуск программ, связь). Ограничения ввода строки: на ПК до 4096 байт,
в ядре до 255.

## Коды ошибок

`vm_run` возвращает `0` при `halt` и отрицательное число при ошибке.

| Код | Имя | Причина |
|-----|-----|---------|
| -1 | `VM_ERR_BADOP` | неизвестная или оборванная команда |
| -2 | `VM_ERR_DS_OVER` | переполнение стека данных |
| -3 | `VM_ERR_DS_UNDER` | на стеке не хватает значений |
| -4 | `VM_ERR_RS_OVER` | переполнение стека возвратов (слишком глубокая рекурсия) |
| -5 | `VM_ERR_RS_UNDER` | `ret` при пустом стеке возвратов |
| -6 | `VM_ERR_MEM` | адрес вне памяти, нет места в куче, неверная метка |
| -7 | `VM_ERR_DIV0` | деление на ноль |
| -8 | `VM_ERR_JUMP` | переход или выполнение за пределами кода |
| -9 | `VM_ERR_STEPS` | исчерпан лимит шагов |
| -10 | `VM_ERR_IMAGE` | повреждённый образ программы |
| -11 | `VM_ERR_SYS` | системный вызов не поддерживается |
| -12 | `VM_ERR_FRAME` | ошибка кадра локальных переменных (слишком глубокая рекурсия по памяти) |
| -13 | `VM_ERR_TRAP` | программа сама остановила себя командой `trap` |

## Ассемблер (`tools/ptasm.py`)

```
; комментарий до конца строки
.data                       ; секция данных
msg:   .string "Привет"     ; байты текста и нуль (только символы до 255)
n:     .word 10, 20         ; 32-битные слова
buf:   .space 16            ; нули
.byte 1, 2, 3               ; байты

.code                       ; секция кода (по умолчанию)
        push msg            ; адрес метки; числа и 'символы' тоже можно
        ld8
        jz конец
        sys 1
конец:
        halt
```

Метки можно использовать до их определения. `push` с меткой всегда занимает 5 байт. Запуск:
`python3 tools/ptasm.py программа.pta программа.ptb`. Пример: `examples/hello.pta`.

## Подключение ВМ к ОС

`vm_t` создаётся функцией `vm_load(образ, память)`, дальше `vm_run(максимум_шагов)`. Системные вызовы реализуются
функцией, которую задаёт владелец ВМ (`vm.sys`): на ПК это `vm/host.c`, в ядре `kernel_sys` в `kernel/kernel.c`.
Общие помощники для вызовов лежат в `vm/vmio.c` (например, превращение UTF-8 в строку Слога), там же номера вызовов.

## Планы

64-битные ячейки или отдельные дробные команды (зависит от решения по дробным числам), вызовы файлов и запуска
программ, доступ к оборудованию для драйверов, таблица экспорта функций модуля.
