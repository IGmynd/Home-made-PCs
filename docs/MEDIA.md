# Заголовок носителя (v1)

Лежит в начале **любого** носителя (дискета, CD, флеш): первые 512 байт, сектор 0. Позволяет системе понять,
что за диск вставлен, не завися от привода. Порядок байтов везде little-endian. Создаётся и проверяется
`tools/mkmedia.py`, читается boot ROM (`boot/boot.c`) и ядром (`kernel/ptfs.c`).

## Раскладка

| Смещение | Размер | Поле | Описание |
|----------|--------|------|----------|
| 0x00 | 4 | magic | ASCII `PTMD` |
| 0x04 | 2 | версия | формат заголовка, сейчас 1 |
| 0x06 | 1 | класс | роль диска, см. ниже |
| 0x07 | 1 | флаги | бит 0: загрузочный |
| 0x08 | 16 | метка | ASCII, добивается нулями (`PT-SYS`, `PT-USER`) |
| 0x18 | 4 | id тома | идентификатор |
| 0x1C | 1 | минимальный профиль | 1 = КПТ, 2 = ПТ |
| 0x1D | 3 | резерв | нули |
| 0x20 | 4 | начало образа | номер сектора (LBA) |
| 0x24 | 4 | длина образа | в секторах |
| 0x28 | 4 | адрес загрузки | куда копировать в ОЗУ (для загрузочных) |
| 0x2C | 4 | точка входа | куда передать управление (для загрузочных) |
| 0x30 | 4 | CRC32 образа | по всем секторам образа, включая добивку нулями |
| 0x34 | 4 | всего блоков | размер носителя в секторах |
| 0x38 | 452 | резерв | нули |
| 0x1FC | 4 | CRC32 заголовка | по байтам `0x00..0x1FB` |

CRC32: стандартный (многочлен `0xEDB88320`, как в zlib).

## Классы носителей

| Класс | Роль | Состояние |
|-------|------|-----------|
| 1 | системный (мастер-дискета): ядро, библиотеки, шелл, драйверы | используется |
| 2 | данные: пользовательские файлы (содержит файловую систему [PTFS](PTFS.md)) | используется |
| 3 | программы | зарезервирован |
| 4 | тяжёлое и ситуативное (большие данные, DVD) | зарезервирован |
| 5 | профиль (личные данные, драйверы оптики) | планируется |

## Правила

- Заголовок с неверным CRC считается повреждённым: носитель отвергается.
- Boot ROM берёт только носитель класса 1 с флагом «загрузочный» и проверяет CRC образа.
- Для носителей данных (класс 2) поля загрузки не используются; целостность файлов обеспечивает
  CRC каждого файла в PTFS, а CRC образа в заголовке при чтении не проверяется (на этом носителе он не
  изменяется при записи файлов).
- Программа в своём заголовке укажет, носители каких классов ей нужны.
- Заголовок кладётся в сектор 0, образ с сектора 1 (`mkmedia.py` собирает образ именно так).

## Создание образа

```
# системная дискета: ядро в образе, загрузка по адресу 0x80100000
python3 tools/mkmedia.py out/floppy.img --kernel out/kernel.bin --label PT-SYS \
        --cls 1 --boot --load 0x80100000 --entry 0x80100000

# пользовательская дискета: в образе файловая система PTFS
python3 tools/mkmedia.py out/floppyB.img --kernel out/fs.img --label PT-USER --cls 2

# проверка
python3 tools/mkmedia.py out/floppy.img --check
```

Размер носителя по умолчанию 2880 секторов (дискета 1,44 МБ). Параметр `--kernel` исторический: это просто
файл-образ, который кладётся после заголовка (у данных там файловая система).
